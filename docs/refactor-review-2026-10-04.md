## 確認範囲

- Bun 1.4.2で `bun run test`（16件、478アサーション）と `bun run build` が通過。
- JavaScriptとTypeScriptの構文解析、`git diff --check` が通過。
- 篇・全文・余話・名句／ハイライト・附録のデータを変更前後で評価し、値と配列順序が一致。
- `src/` と `dist/` の全15ファイルで、相対パスの一覧とファイル内容が一致。
- Codex内蔵の実ブラウザで1440×1000px、420×912pxを確認。
- 総覧、十三篇、附録の全15画面で、本文・上端・目次のHTMLとタイトルを変更前後で比較。各サイクルで両画面幅とも一致し、ページ全体の横はみ出しもなかった。
- CSSを変更した見出し、擬似要素、本文、竹簡、組み方ボタンなどの計算済みスタイルを比較。通常表示とダーク表示では全画面・両画面幅で一致。削除した未使用のカスタムプロパティ自体は比較対象から除いた。
- 印刷表示の計算済みスタイルは、総覧・第一篇・附録で一致。
- 名句への移動、進言への復帰、本文へ移動、前後の篇、ブラウザ履歴、目次の開閉／Escape／篇切り替えを比較。遷移完了後のハッシュ・フォーカス・選択状態・スクロール位置が一致。
- 縦書きの前後移動、終端でのボタン無効化、ホイール、横書き／縦書き切り替えで位置とボタン状態が一致。
- 目次を開いた状態からデスクトップ幅に変えると、従来どおり目次が閉じた。
- 先頭ゼロの篇番号、範囲外の篇番号、`#reading` の直接アクセスの解釈が一致。
- LocalWebの `sonshi-guide.localhost` とTailscaleの `/apps/sonshi-guide/` で生成物が読み込まれ、確認した画面のHTMLが変更前と一致。ブラウザエラーはなかった。

## 検証の限界

- 420×912pxの確認はブラウザの画面幅による検証であり、iPhone Air実機やSafariでの確認ではない。
- プロジェクトには `typecheck` の設定がない。型検査用の依存は追加せず、構文解析・テスト・ビルドで検証した。
- 印刷はブラウザの印刷メディア設定による比較で、実際の紙への出力は確認していない。

## 構造をこれ以上分割しなかった理由

データ、HTML生成、画面制御の三つの責務を分け、繰り返し使う小さな処理だけを共通化した。
画面ごとに異なるマークアップやメディアクエリは、その場で読める形を維持した。
さらに汎用的なレンダラー、ルーター、コンポーネント層を導入すると、追うファイルや間接参照が増えるため見送った。
